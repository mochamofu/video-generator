# 引き継ぎメモ (HANDOFF.md) スキル

引数が `check` の場合は「監査モード」、それ以外は「更新モード」で動く。

## 共通の前提

- 対象ファイルはリポジトリ直下の `HANDOFF.md`
- 読み手は**このセッションの記憶を一切持たない新しいClaude**である。人間向けの要約ではなく、復帰手順書として書く
- 合格条件: 読み手がこのファイル**だけ**を読んで、質問なしで作業を再開できること

## 更新モード (`/handoff`)

1. `HANDOFF.md` がなければ下のテンプレートで新規作成、あれば**既存の内容を保持したまま**現在のセッションの内容で更新する（過去の記録を消さない。古くなった項目は消すのではなく「済」「無効」と明記する）
2. 書くときの禁止事項:
   - リンク・ID・ファイルパス・コマンドの省略禁止（「例のシート」「〜など」は禁止。必ずURLか正確な名前で書く）
   - 未検証の事項を「完了」と書くことの禁止（[検証済み] / [未検証] を必ず付ける）
   - 「自明だから省略」の禁止。自分が今知っていることは、次のセッションは知らない
3. 各セクションを埋められない場合は空欄にせず `（該当なし)` か `（不明: 理由）` と書く
4. 更新後、`CLAUDE.md` に「セッション開始時にまず `HANDOFF.md` を読むこと」という参照が無ければ追記する

### テンプレート

```markdown
# HANDOFF — 引き継ぎメモ
最終更新: YYYY-MM-DD (セッション: 何をしていたか一言)

## 1. 正の対象（省略・「など」禁止）
- リポジトリ/ブランチ:
- 触ってよいファイル・サービス（URL/IDを列挙）:
- 触ってはいけないもの:

## 2. 完了したこと（[検証済み]/[未検証] を明記）
-

## 3. 未完了と、次の最初の一歩
- 残タスク:
- 次のセッションはまずこれをやる:

## 4. 決定事項と却下した案（理由つき）
-

## 5. ハマりどころ・環境の罠
- （例: この環境から〜のAPIは403になる / 認証キーは〜にある / 〜は手動手順が必要）

## 6. ユーザーからの訂正・指摘（最重要。絶対に消さない）
- （例: 「生徒個別管理表」は進捗管理ではなく補助金の管理会計のこと）
```

## 監査モード (`/handoff check`)

自分がこのセッションで得た文脈を**すべて忘れたふり**をして、`HANDOFF.md` だけを読んで以下を出力する。ほかのファイルや会話履歴で補完してはいけない。

1. **再開シミュレーション**: このメモだけで作業を再開するとしたら、最初に何をするか。着手できないならどこで詰まるか
2. **不足リスト**: 欠けている情報を、具体的な質問の形で列挙する（例:「補助金の締め日はいつか」ではなく書き手が答えられる形で）
3. **セクション別判定**: テンプレートの各セクションに 合格 / 要修正 / 空欄 を付ける
4. 最後に、不足リストを反映した修正を提案し、ユーザーの了承を得てから `HANDOFF.md` を更新する

## 使い方の目安

- 作業の節目（機能が1つ完成した、方針が変わった、ユーザーから訂正を受けた）ごとに `/handoff`
- セッションを終える前に `/handoff check` で不足を潰してから終了する
